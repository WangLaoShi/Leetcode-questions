# 身份匹配与冲突规则

导入顺序固定为 leetcode-api、neenza、doocs。先写入带内部 ID 的来源，doocs 再用展示题号和 slug 对齐。

## 匹配顺序

只在同一 `platform` 且同一 `site` 内匹配。

1. `platform_question_id` 非空且命中：视为同一题。slug 或展示题号不一致时保留已有身份，并记 `identity_field_mismatch`，不覆盖。
2. slug 与展示题号指向同一条身份：命中。
3. 只有 slug 或只有展示题号，且另一字段为空或相等：命中，并补上缺失标识。
4. slug 与展示题号指向不同题目，或命中记录的另一字段冲突：隔离。记入 `data_issue`（`identity_conflict`）和待处理清单，不新建题目，不覆盖。
5. 没有任何标识命中：新建题目。内部主键自增，不使用展示题号。
6. 不按标题自动合并。leetcode.cn 与 leetcode.com 即使 slug 相同也不合并，只写入 `reports/cross-site-candidates.jsonl` 待核实。

某次快照没有返回一道题时，不删除本地题目。

## 内容

- 同一来源、同一路径、同一定位符、同一内容哈希：跳过，不新增题目、题干、示例、提示、模板或标签。
- 同一来源内容哈希变化：新版本，`revision` 加一，旧版本保留。示例和提示挂在具体 `content_id` 上。
- 同一题目、同一语言、不同来源的正文都保留。`is_current` 只标一条：有正文者优先，来源优先顺序为 leetcode-api、neenza、doocs，同来源取更高修订号。
- 比较前去掉空白和简单标记。比较键不同则记 `content_conflict`，不把两篇正文拼接。一边为空只记缺失，不算冲突。
- 类别、难度、会员标志：已有值为空时用新值补上；两边都有且不同则记冲突，不覆盖。

## 其他对象

- 标签按（词表, code）去重，题目与标签的关联表拒绝重复。
- 模板按（题目, 语言, 模板哈希）去重。当前模板按同样的来源优先顺序选择。
- 模板超过明显的空函数体规模时记 `suspected_implementation`，仍保存原文供抽查，不把它写成答案。
- 问题指纹全局唯一，重复导入不复制 `data_issue`。

## 事务

一整批导入放在一个事务里，每条记录一个 savepoint。单条失败只回滚该条。有失败或身份隔离时批次状态为 `partial` 或 `failed`，不报全量成功。`--dry-run` 在统计之后回滚整个事务。
